# Marketing website redesign — public homepage, nav, pricing, footer (v1)

The public marketing surface was rebuilt into a single editorial homepage (`web/src/screens/Landing.jsx`) composed of thirteen self-contained sections under `web/src/screens/home/`, a minimal sticky nav with a Product mega-menu and a mobile disclosure sheet (`web/src/components/PublicShell.jsx`), a four-tier pricing page, and a six-column footer. The visual language is premium light-mode: a `.mkt`/`.mkt-nav`-scoped token layer added to the end of `styles.css` (white canvas, near-black ink, hairline borders, selective purple reusing the existing brand vars) with real product-frame markup — sidebars, rooms, composers, artifact viewers — carrying the page instead of generic AI art. Auth CTAs route through the existing `startLogin` helper, pricing preserves the server-built Stripe checkout, and honesty constraints (only Slack real / rest "Upcoming", placeholder social proof, no infra vocabulary in the virtual-computer section) hold up under inspection. Motion is CSS-only, keyed off a single IntersectionObserver boolean, and stilled under `prefers-reduced-motion`.

Watch for: (1) the Product mega-menu uses `role="menu"`/`role="menuitem"` on plain navigation links, which invokes an application-menu keyboard contract the component doesn't implement (**likely**); (2) `Landing.jsx` renders `<TopNav>` + `<main>` directly rather than through `PublicShell`, so the shell/landing chrome paths have diverged and can drift (**confirmed**, low severity); (3) two decorative headings (`<h3># Growth>`, `<h4>Weekly Growth Brief`) sit inside `aria-hidden` frames but still exist in the raw heading structure (**possible**, low severity).

**Verdict**: APPROVED

## High-level view

The homepage narrative is ordered exactly as specified — hero, trust strip, platform story, team tabs, then the Companions/Rooms/Routines/Artifacts vocabulary, then connectors, live demo, virtual computer, social proof, and final CTA — with all verbatim copy present and a single `<h1>`. Sections live as small components so the page reads as a table of contents.

Marketing isolation is clean: the `home/` components import only the presentational `Companion` character and the local `useReveal` hook. Nothing pulls in `api.js`, the app `Shell`, or the live `Room`/`Composer`, so the product frames are static markup that can't break outside the authenticated app. Auth CTAs go through `startLogin` with the specified `returnTo` targets; pricing keeps the signed-out→signup / signed-in→server-built-checkout split with an inline error path.

The design tokens are strictly additive under `.mkt`/`.mkt-nav`; the app's existing `:root` tokens and both dark blocks in `styles.css` are untouched, and no authenticated route or `src/app/` file appears in the diff. The public site is forced light by `theme.js`, so there's no dark marketing variant to maintain.

Honesty constraints are respected. The trust strip and connectors list only Slack as real and tag everything else "Upcoming"; social proof is an explicitly-labelled empty case-study template with no invented logos, testimonials, or metrics; the virtual-computer section describes only what a companion does with a computer, never how it runs — no EC2/container/queue vocabulary in rendered copy.

Accessibility is mostly strong — a real ARIA tablist with Arrow/Home/End roving focus, mega-menu `aria-expanded`/`aria-haspopup` with Escape and outside-click close, a mobile disclosure equivalent, and motion gated by `prefers-reduced-motion`. The one soft spot is the `role="menu"` choice on the mega-menu. Responsive behavior reflows every fixed product frame at 880/760/560px breakpoints and guards page overflow with `overflow-x: clip`.

<summary>Issues (4)</summary>

1. **Mega-menu menu-role semantics** — the Product panel uses `role="menu"` + `role="menuitem"` on navigation `Link`s, which tells assistive tech to expect application-menu arrow-key navigation that isn't wired up. Prefer a plain disclosure (`role` omitted, links in a `<ul>`) or implement the menu keyboard model.
2. **Landing bypasses PublicShell** — `Landing.jsx` renders `<TopNav>`/`<PublicFooter>` and its own `<main>` directly instead of wrapping in `PublicShell`, duplicating the chrome contract; consider rendering through `PublicShell` (or documenting why the homepage is intentionally special) so the two paths don't drift.
3. **Decorative headings in raw outline** — `<h3># Growth>` (ProductFrame) and `<h4>Weekly Growth Brief` (Artifacts) live inside `aria-hidden="true"` frames but remain in the DOM heading sequence (and skip a level, h2→h4); swap them to non-heading elements to keep the outline clean for tools that ignore `aria-hidden`.
4. **Progressive-tense status labels in LiveDemo** — the per-agent `status` strings ("Searching the web", "Reviewing findings") are present-progressive while the spec's activity vocabulary is past-tense (Searched/Read/Analyzed/…); the activity verbs themselves are correct, so this is cosmetic consistency only.

### Auth CTA wiring

Every "start" entry point resolves through the shared `startLogin(loginWithRedirect, …)` helper in `auth0.jsx`, which maps `signup:true` to Auth0's `screen_hint:'signup'` and carries `returnTo` in `appState`. The nav "Sign in" uses `{ returnTo: '/' }`; the nav "Start free", the hero "Start for free", and the final CTA all use `{ signup:true, returnTo:'/welcome' }`, matching the spec exactly. The Landing test asserts the hero path fires with `{ signup:true, returnTo:'/welcome' }`.

Pricing's `getStarted(planKey)` keeps the correct branch: signed-out visitors get the signup redirect (no premature checkout), signed-in visitors call `api.billing.checkout({ planKey })` and follow the returned `url`, and a rejected promise surfaces an inline `error` and clears the busy state. Success/cancel URLs are built server-side from the request Origin, not passed from the client — the right call to avoid an open redirect through Stripe. Enterprise renders a "Talk to sales" link, so `contact:true` never reaches the billing API.

### Marketing isolation

Grep across `screens/home/*.jsx` confirms the only cross-module imports are `../../characters/Companion` and the local `./useReveal`; `Companion` itself imports only `./archetypes`. No `home/` component references `api.js`, the app `Shell`, or the live `Room`/`Sections`/`Composer`, so the product frames are inert DOM that can't break outside the authenticated app or drag a backend dependency onto the marketing page.

### Design-token additivity

The marketing layer is appended after the app CSS and scoped to `.mkt, .mkt-nav`, defining `--mkt-*` properties that either introduce new light values or alias existing brand vars (`--mkt-accent: var(--brand-3)`). The diff does not touch the `:root` token block, the `@media (prefers-color-scheme: dark)` block, or the `:root[data-theme="dark"]` block — grep for `color-scheme: dark`/`data-theme="dark"` returns zero hits inside the diff, so the authenticated theme is unaffected.

### Honesty constraints

The trust strip and connectors render the same set with `Slack` as the sole `upcoming:false` entry and GitHub/Drive/Gmail/Calendar/Notion/Microsoft tagged `Upcoming`; wordmarks are plain text, no fabricated logos, and the connectors flow reuses those names so no partnership is implied beyond the tags. `SocialProof` is a labelled empty template — a "Coming soon" tag over five structural slots (Quote / Company / Workflow before / Workflow with / Measured outcome), no invented logos, testimonials, usage counts, or metrics. `VirtualComputer` renders "Not limited to a chat box." / "Give your AI a computer." with the verbatim supporting line and Maya's-computer example; grepping the rendered strings finds no EC2, container, worker-queue, or backend-infra term.

### Accessibility

The team use-cases tablist is correct: `role="tablist"`, roving `tabIndex`, `aria-selected`/`aria-controls`/`aria-labelledby`, and `ArrowLeft`/`ArrowRight`/`Home`/`End` moving selection and focus together (automatic activation).

The mega-menu trigger carries `aria-expanded`/`aria-haspopup`/`aria-controls` and closes on Escape, outside `mousedown`, and route change, with the mobile hamburger mirroring it via a flattened disclosure sheet. The gap is semantic: the desktop panel is `role="menu"` with `role="menuitem"` links. That role pair signals an application menu whose items are arrow-key-navigated (not Tab) and which the component does not implement, so a screen reader can announce behavior the widget doesn't have. A plain disclosure (drop the roles, keep the links in a list) matches the actual behavior. Not blocking — the links stay reachable and operable by Tab/Enter — but it's the one a11y item worth fixing.

The page has a single `<h1>` (hero) and section `<h2>`s in order. Two decorative headings remain — `<h3># Growth>` (`ProductFrame`) and `<h4>Weekly Growth Brief` (`Artifacts`) — nested inside `aria-hidden="true"` frames, so they're pruned from the accessibility tree for conforming AT. They still sit in the raw DOM heading sequence (and the Artifacts one jumps h2→h4), which a tool that ignores `aria-hidden` would flag; converting them to spans removes the ambiguity.

### Responsive behavior

`.mkt { overflow-x: clip }` guards page-level horizontal scroll, and every fixed-composition frame reflows: feature grids and the teams panel collapse to one column at 880px; at 560px the `pf-body` sidebar is hidden, the room's fixed 150px rail stacks under the thread (`.pf-room-cols` → 1fr, which the author notes would otherwise overrun a ~360px viewport), the connector-tool and screen-plans grids go single-column, and the hero CTAs stack full-width. The team tab strip uses `overflow-x: auto` to scroll rather than overflow. The collapsed nav keeps both CTAs in the mobile sheet, so "Start free" stays reachable on a phone, and narrative order is preserved because the same component sequence reflows.

### Motion

`useReveal` flips one `is-in` boolean on entry and falls back to `shown:true` when `IntersectionObserver` is absent (jsdom), so nothing is ever hidden without motion. Two `@media (prefers-reduced-motion: reduce)` blocks force `opacity:1; transform:none; transition:none` on the flow/connector/demo/computer-task animations and freeze the artifact bar and screen cursor, so the reduced-motion final state is legible regardless of whether `is-in` fired. No scroll-jacking or parallax.

### Exact copy

Verbatim strings are present and unaltered: hero headline/lede/CTAs/microcopy; trust headline "One workspace. Your models, tools, files, teammates, and AI companions."; platform eyebrow/title and "Prepare our Monday growth meeting."; the six team labels with per-team copy; the four product-section headlines; Routines "Competitive Intelligence" / "Every Monday · 8:00 AM"; connectors "Work where your work already lives."; virtual-computer eyebrow/title/supporting line; final CTA "Build your AI team." / "Start with one companion. Give it a job. See what happens next." / "Start free"; footer groups Product/Solutions/Resources/Developers/Company/Legal.

### Tests and build

`npm run build` is clean and `npm test` reports 29 files / 197 passing. `Landing.test.jsx` covers the hero h1, the microcopy, the signup CTA payload, the four anchor ids, and the tablist keyboard swap; `Pricing.test.jsx` asserts signed-out→signup, signed-in→`checkout({planKey:'business'})`, and the inline-error path. Not tested: mega-menu open/Escape/outside-click, the mobile disclosure sheet, and `useReveal`'s observer fallback — verified only by inspection.
